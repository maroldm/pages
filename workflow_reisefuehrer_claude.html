Commit & Push
Working Copy

7 Quelltext lesen — wo und wie
ZielWerkzeugVorgehen
Was liegt auf GitHub? github.com Repository → Ordner → Datei antippen → Quelltext mit Zeilennummern sichtbar. Dort nach Begriffen scrollen.
Was liefert GitHub Pages aus? github.com Direkte Raw-URL aufrufen: raw.githubusercontent.com/maroldm/pages/main/pfad/datei.html — zeigt exakt den ausgelieferten Inhalt.
Was sieht der Browser? Edge / Safari view-source: funktioniert in Edge auf iPhone nicht. Stattdessen: github.com → Datei direkt anschauen.
Einzelne Zeile finden github.com Datei auf github.com öffnen → Drei-Punkte-Menü → "In place" bearbeiten → Strg+F funktioniert im Browser.
Datei bearbeiten github.dev Auf github.com Datei öffnen → Drei-Punkte → github.dev → Vollständiger Editor. Rechtsklick auf Datei im Explorer → Umbenennen möglich.
Einzelnes Bild prüfen Edge Direkte URL aufrufen: maroldm.github.io/pages/2026_cesenatico/ravenna/img/dateiname.jpeg — Bild erscheint oder 404.
github.dev vs. github.com: github.com zeigt Dateien read-only. github.dev (Punkt-Taste oder Drei-Punkte-Menü) öffnet den echten Editor mit Umbenennen, Verschieben per Rechtsklick, Commit & Push direkt im Browser.
8 Notfallplan
!
Fast-Forward Fehler beim Push
Working Copy

"Änderungen können nicht gepusht werden, da kein Fast-Forward möglich war."

Ursache: GitHub hat einen neueren Commit als Working Copy — z.B. nach Änderungen über github.dev oder github.com.

Lösung: Fingerabdruck → Pull → danach Push. Pull holt den neueren Stand herunter, dann kann gepusht werden.

Pull macht nichts kaputt — es holt nur den Stand der bereits auf GitHub liegt.
!
Bilder erscheinen nicht (Fragezeichen)
Browser

Checkliste in dieser Reihenfolge:

1. Bild-URL direkt testen: maroldm.github.io/.../img/dateiname.jpeg — 404 oder Bild?

2. Falls 404: Datei überhaupt in Working Copy unter img/? Dateiname exakt korrekt (Unterstrich, kein Bindestrich, kein Umlaut)?

3. Falls Bild erscheint aber nicht im HTML: HTML auf github.com prüfen — steht dort .jpeg oder .jpg? Endungen müssen exakt übereinstimmen.

4. GitHub Actions grünen Haken? Falls nicht — warten.

!
Alter Link funktioniert nicht mehr
github.dev

Ursache: Datei oder Ordner wurde umbenannt oder verschoben.

📱 iPhone — github.dev
💻 Notebook — github.dev
github.com → Datei → Drei-Punkte → github.dev → Datei im Explorer lang drücken → Umbenennen → neuen Pfad eingeben → Commit & Push.
github.com → Datei → Drei-Punkte → github.dev → Datei im Explorer rechtsklicken → Umbenennen oder per Drag & Drop in Zielordner ziehen → Commit & Push.
Nicht über github.com Datei-Editor versuchen — der ../ Trick funktioniert dort nicht ("malformed path").
9 Bekannte Fallstricke
Bindestrich statt Unterstrich: galla-placidia-aussen.jpeg vs. galla_placidia_aussen.jpeg — HTML findet die Datei nicht. Immer Unterstrich.
Umlaute in Dateinamen: kreuzgewölbe.jpeg → kreuzgewoelbe.jpeg. Umlaute in Dateinamen vermeiden.
.jpg vs. .jpeg: iPhone speichert als .jpeg. HTML muss dieselbe Endung haben. Claude liefert seit Juni 2026 immer .jpeg.
Duplikate durch Import: Wenn eine Datei bereits existiert → Working Copy legt datei-2.html an. Immer zuerst alte löschen, dann neue importieren.
Push-Toggle vergessen: Wenn Toggle grau ist, wird nur committed, nicht gepusht. Nichts ist live bis Push erfolgt.
Häkchen vergessen: Vor dem Commit müssen alle Dateien links angehakt sein — sonst werden nur einige committed.
Immer zuerst GitHub Actions prüfen bevor man annimmt, dass etwas live ist oder nicht.
OneDrive ist nur Zwischenlager — nach dem Import in Working Copy ist OneDrive irrelevant für GitHub.
10 Prompt-Vorlage — neuer Reiseführer

Dieser Prompt liefert zuverlässig eine fertige HTML im etablierten Stil — mit Bildnamen-Mapping und allen gelernten Konventionen. Den Textblock unten lang drücken → Alles auswählen → Kopieren.

Prompt — zum Kopieren
// Prompt für Claude — neuer Reiseführer Ich möchte eine HTML-Reiseführer-Seite für [ORT] erstellen. Fotos: Ich lade [N] Fotos hoch (iPhone-Namen IMG_xxxx). Bitte identifiziere jedes Foto und liste: - Vorgeschlagener Dateiname nach Schema: ort_beschreibung.jpeg (Unterstrich, kein Bindestrich, kein Umlaut, alles klein) - Kurze Inhaltsbeschreibung für Bildunterschrift HTML-Anforderungen: - Dateiname: index.html (liegt in 2026_xxx/ort/) - Bilder in img/ relativ zur HTML - Kein Leaflet — SVG-Karte oder Google Maps Link - Hochformat-Fotos: object-position top - Querformat-Fotos: object-position center - Endung .jpeg (nicht .jpg) - Stil: Playfair Display / Source Sans 3, dunkler Header, Stationskarten, Highlight-Boxen Stilprinzipien: - Pars pro Toto: lieber wenige Orte wählen, die stellvertretend die Geschichte der Stadt erzählen — nicht alle Sehenswürdigkeiten abhaken - Geschichte an Personen festmachen: Wer hat das gebaut, warum, was hat es ihn gekostet, was ist danach passiert — keine abstrakten Jahreszahlen ohne Kontext - Atmosphäre vor Fakten: was wirkt, was fühlt sich an, wie ändert sich das Licht — bevor erklärt wird was ein Ort ist - Für interessierte Laien lesbar, nicht für Fachpublikum — aber keine Vereinfachung - Praktisches eingebettet: Öffnungszeiten, Tickets, Hinweise direkt beim Ort Inhalt — Stationen: [Stichpunkte: was gesehen, was aufgefallen, eigene Beobachtungen vor Ort]
Bildnamen-Mapping: Claude listet alle Fotos mit vorgeschlagenem Dateinamen — so kann man IMG_xxxx direkt in OneDrive umbenennen ohne raten zu müssen.
Dateiname immer index.html — das Verzeichnis ist der sprechende Name. 2026_cesenatico/rimini/index.html → erreichbar als maroldm.github.io/pages/2026_cesenatico/rimini/

Stilprinzip — Pars pro Toto

Nicht alle Sehenswürdigkeiten einer Stadt abarbeiten — sondern gezielt auswählen: welche Orte erzählen stellvertretend die Geschichte dieser Stadt? Ein Triumphbogen erklärt das Imperium. Ein halbfertiger Tempel erklärt die Renaissance und einen Papststreit. Eine Mosaikkirche erklärt zwei Theologien und einen Epochenbruch.

Geschichte an Personen festmachen: Galla Placidia als Geisel, Regentin, Bauherrin. Sigismondo Malatesta als Mäzen und exkommunizierter Heidenprovokateur. Theodora als Tochter eines Zirkuswärters auf dem Kaiserthron. Die Person trägt die Geschichte — nicht das Datum.

Atmosphäre vor Fakten: Der Übergang vom grellen Tageslicht in die Halbdunkelheit von Galla Placidia. Das Flimmern der Goldtesserae bei Bewegung. Diese Sätze laden ein — die anderen informieren.

iPhone Shortcuts — geplante Verbesserungen

Der aktuelle Workflow hat zwei manuelle Engpässe die sich mit iOS Shortcuts automatisieren lassen. Shortcuts ist Apples eingebaute Automatisierungsapp — app-übergreifend, kein Code, visuelle Bausteine.

Geplant 1 — Bilder komprimieren und umbenennen:
Aktuell: Fotos sind 3–8 MB groß (iPhone Originalauflösung), Ladezeit der Webseite spürbar. Ziel: Shortcut der ein oder mehrere Fotos nimmt, auf einen definierten Prozentsatz der Originalgröße reduziert (kein fixer Wert, sondern relativ), nach Eingabe eines Namens umbenennt, und direkt in OneDrive speichert — alles in einem Tap.

Geplant 2 — Dateiname vergeben:
Aktuell: Umbenennen in OneDrive per Hand, Thumbnail-Zuordnung manchmal fehleranfällig. Ziel: Shortcut fragt beim Speichern direkt nach dem Zielnamen — kein nachträgliches Umbenennen mehr nötig.

Offen / noch nicht durchdacht:
Working Copy hat eine Shortcuts-Integration — theoretisch könnte auch Commit und Push in einen Shortcut eingebaut werden. Ob das den Aufwand lohnt und wie es mit der Mehrfachauswahl von Dateien zusammenspielt, ist noch nicht evaluiert.

Dieser Abschnitt wird ergänzt sobald die Shortcuts erarbeitet und getestet sind.
